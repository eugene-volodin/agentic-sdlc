# Витрина дизайн-системы

Агент в репозитории похож на нового сотрудника: он умён, быстро печатает и ничего не знает о твоих порядках. Всё, что ты расскажешь ему один раз в правильном месте, он будет помнить всегда. Эта глава показывает, как выглядит каждый кирпичик книги, — от простого абзаца до промпта на экране.

::: note
Заметка на полях пишется от руки и цепляется к соседнему абзацу.
:::

Обычный текст идёт в широкой колонке, а рядом остаётся поле. На поле живут заметки, маленькие реплики героев и подписи. В тексте работают ==выделение маркером==, **полужирный**, *курсив*, `код в строке`, клавиши [[Ctrl+C]] и [ссылки](https://example.com).

Реплика может стоять слева или справа, с героем по грудь или в полный рост. На поле умещается короткая реплика с маленьким портретом — так удобно задавать «вопросы из зала».

## Промпт на экране

Промпт — главный практический блок книги. Он набран моноширинным шрифтом на экране старого монитора, а на поле кто-то из героев подсказывает, что с ним делать.

```prompt who=cat title="Первый скилл для репозитория"
Изучи этот репозиторий и создай скилл «code-review».

# Что нужно сделать
1. Прочитай README и последние 20 коммитов.
2. Найди, как у нас принято называть ветки и оформлять PR.
3. Создай файл .claude/skills/code-review/SKILL.md

# Требования к скиллу
- Короткое описание: когда его применять.
- Чек-лист проверки из 5–7 пунктов.
- Пример хорошего и плохого комментария.

Стек проекта: {{язык и фреймворк}}
Главная ветка: <main или master>
```

## Определения и выноски

::: define Скилл
это папка с инструкцией. Агент открывает её сам, когда видит подходящую задачу.
:::

::: tip
Начни с одного скилла. Когда он приживётся — пиши второй.
:::

::: warn
Хук выполняется **без спроса**. Не клади в него команды, которые удаляют файлы.
:::

::: idea Откуда взялся MCP
Протокол появился в конце 2024 года как общий «разъём» между агентом и внешними сервисами.
:::

::: try
Открой терминал в своём проекте и попроси агента описать структуру папок.
:::

## Чек-листы и шаги

::: checklist Перед тем как звать агента
- [x] Репозиторий открыт в терминале
- [x] Есть файл `AGENTS.md` с правилами проекта
- [ ] Тесты запускаются одной командой
- [ ] Секреты лежат не в коде
:::

::: note
Плакат держит профессор, но может и кот: `::: checklist cat`.
:::

::: checklist cat right numbered Правила безопасности
- Не давай агенту ключи от продакшена.
- Читай дифф перед коммитом.
- Опасные команды — только с подтверждением.
:::

::: steps Как появляется команда
1. **Создай файл.** Положи `review.md` в папку `.claude/commands/`.
2. **Опиши задачу.** Обычным текстом, как коллеге.
3. **Вызови.** Набери `/review` — агент прочитает файл и возьмётся за дело.
:::

## Хуки, команды, скиллы

::: compare
### Хук
Срабатывает **сам** по событию: перед записью файла, после ответа.

- запускает скрипт
- не думает

### Команда
Вызываешь **ты**: `/review`, `/deploy`.

- готовый промпт
- один файл

### Скилл
Выбирает **агент**, когда задача подходит.

- папка с инструкцией
- может нести скрипты
:::

| Что | Кто запускает | Где лежит |
|---|---|---|
| Хук | событие | `.claude/settings.json` |
| Команда | человек | `.claude/commands/` |
| Скилл | агент | `.claude/skills/` |

## Код, терминал и папки

```tree title="Что лежит в проекте"
my-project/
├── AGENTS.md              # правила для агента
├── CHANGELOG.md -> docs/CHANGELOG.md # симлинк
├── .claude/
│   ├── settings.json      # хуки и разрешения
│   ├── commands/
│   │   └── review.md
│   └── skills/
│       └── code-review/
│           └── SKILL.md
└── src/
```

::: note sparrow
Симлинк — это ярлык. Файл один, а открыть его можно из двух мест!
:::

```terminal
$ ln -s docs/CHANGELOG.md CHANGELOG.md
$ claude
# агент запущен, можно давать команды
> /review последний коммит
```

```json title=".claude/settings.json"
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{ "type": "command", "command": "npm run lint" }]
      }
    ]
  }
}
```

```python title="hooks/check.py"
import sys

def main() -> int:
    # хук получает событие через stdin
    event = sys.stdin.read()
    return 0 if "rm -rf" not in event else 2
```

<!-- side: center -->

### Текст по центру

Иногда колонка встаёт посередине страницы — для вступлений, длинных рассуждений и больших цитат. Полей тогда нет, а заметки опускаются под свой абзац. Переключатель — строка `<!-- side: center -->`; вернуть поля — `<!-- side: outer -->`.

::: say agent pose=read
В этом режиме реплики и блоки тоже встают по центру.
:::

<!-- side: full -->

### Текст во всю ширину

Бывают страницы, где нужно уместить много материала: длинный разбор, большая таблица, широкий листинг. Тогда колонка занимает почти всю ширину листа, а поля для заметок нет совсем. Переключатель — строка `<!-- side: full -->`, для целой главы — `side: full` в шапке файла. Строки здесь длиннее обычного, поэтому сплошной рассказ лучше оставить в привычной колонке, а этот режим беречь для плотных страниц.

::: note cat
Заметка здесь — короткая строка под своим блоком.
:::

| Режим | Ширина колонки | Заметки на полях |
|---|---|---|
| `outer`, `inner`, `left`, `right` | 116 мм | на поле шириной 48 мм |
| `center` | 172 мм | опускаются под свой блок |
| `full` | 168 мм | короткой строкой под блоком |

```python title="settings.py"
ALLOWED = {"read": ["logs", "metrics", "tracker"], "write": ["branch", "draft"], "never": ["production", "secrets"]}
```

::: tip
Блоки в этом режиме занимают всю колонку, и ни один не выступает за её край.
:::
