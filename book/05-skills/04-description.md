## Описание скилла

Текст скилла модель увидит, только когда запросит его у агента, а до этого у неё перед глазами только список названий и описаний. Поэтому, как бы хорошо ни был написан сам скилл, сработает он или нет, решает его **описание**. Если в нём не окажется тех слов, которыми ты обычно формулируешь задачу, модель просто не догадается, что для неё у тебя есть готовый плейбук, и сделает всё по-своему.

Хорошее описание отвечает на три вопроса — что скилл делает, когда его применять и когда не применять. «Когда применять» лучше писать словами, которые реально говорит человек, а в «когда не применять» сразу называть скилл, который нужно взять вместо этого.

::: dodont
- Помогает с фича-флагами
+ Заводит новый фича-флаг в коде, в конфигурации и в A/B-платформе. Применяй, когда просят «закрыть фичу флагом» или «завести флаг»
- Работает с базой данных
+ Подключает новую реплику к кластеру Postgres. Применяй, когда просят «добавить реплику» или «поднять ноду на чтение». Не применяй, чтобы переключить мастер, — для этого скилл postgres-switchover
:::

Если скилл не срабатывает, когда должен, допиши в описание те слова, которыми ты сам ставишь агенту такую задачу, например «закрой фичу флагом». А если он, наоборот, срабатывает там, где не нужен, допиши, когда его применять не надо. И самый простой способ понять, чего описанию не хватает, — спросить у агента, когда бы он использовал этот скилл, и послушать, как он своими словами перескажет описание.

::: note cat
В списке скиллов описание обрезается на 1536 знаках, так что главное пиши в начале — [code.claude.com](https://code.claude.com/docs/en/skills)
:::

::: note sparrow
А если поставить сразу сто скиллов, агент будет уметь всё?
:::

Скиллов может быть много, но и тут есть разумный предел. Описания всех скиллов лежат в контексте каждой сессии, и Claude Code отводит под весь их список не больше одного процента контекстного окна. Когда скиллов становится слишком много, он начинает выбрасывать описания тех, которые ты вызываешь реже всего, — название в списке остаётся, а слов, по которым агент понял бы, когда скилл нужен, — уже нет.

::: warn Ошибка новичка
Найти где-нибудь подборку чужих скиллов и ставить их пачками, без разбора. Их описания в каждой сессии занимают тот же один процент окна, что и твои, даже если ни разу тебе не пригодятся. Модель у тебя в итоге работает просто в мусоре, а твои собственные скиллы теряются среди чужих
:::

Чтобы понять, сколько места занимают скиллы и какими из них ты вообще пользуешься, запусти в Claude Code команду `/skill-doctor`. Она покажет, сколько места в контексте занимает каждый скилл и как часто ты его вызываешь, найдёт те, что ни разу не вызывались, и подскажет, где их отключить, — и начинать отключать лучше с тех из них, что занимают больше всего места.

::: note cat
`/skill-doctor` есть в Claude Code с версии 2.1.252 — [code.claude.com](https://code.claude.com/docs/en/skills)
:::
