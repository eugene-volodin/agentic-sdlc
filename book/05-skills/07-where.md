## Где лежат скиллы

Скилл можно положить в репозиторий, в его подпапку или к себе в домашнюю папку, и от этого зависит, у кого он будет работать.

| Где лежит | Путь | У кого работает |
|---|---|---|
| В репозитории | `.claude/skills/<имя>/SKILL.md` | у всех, кто работает с этим репозиторием, — коммить его вместе с кодом |
| В подпапке репозитория | `<папка>/.claude/skills/<имя>/SKILL.md` | у всех, но только когда агент работает с файлами этой папки, — удобно в монорепозитории |
| В домашней папке | `~/.claude/skills/<имя>/SKILL.md` | только у тебя, зато во всех твоих проектах |

Скиллы в репозитории — это общие плейбуки команды. Подключение реплики, новый модуль, фича-флаг, общий скилл ревью — всё это должно лежать в репозитории и проходить ревью, как код, чтобы у каждого разработчика агент работал по одним и тем же правилам.

А в домашнюю папку стоит класть то, что нужно только тебе. Мой `/pr-review`, например, лежит у меня в домашней папке, а не в репозитории, ведь в нём собраны мои собственные правила ревью, которые отражают исключительно мой вкус.

::: note cat
Если скилл с одним и тем же именем есть и у тебя в домашней папке, и в репозитории, по команде `/имя` запустится твой личный — [code.claude.com](https://code.claude.com/docs/en/skills)
:::

Твоя команда может работать не только с Claude Code. При этом у каждого агента своя папка для скиллов — у Claude Code это `.claude/skills/`, у Codex — `.agents/skills/`. Поэтому все скиллы удобно держать в одной общей папке, а для каждого агента сделать на неё **символьную ссылку** (symlink — файл-ярлык, который указывает на другую папку), и тогда один и тот же скилл прочитают все агенты, с которыми вы работаете.

::: note cat
На Windows Git по умолчанию символьные ссылки не создаёт, их включают настройкой `core.symlinks=true`, а без прав администратора создавать их можно, только включив в Windows режим разработчика — [gitforwindows.org](https://gitforwindows.org/symbolic-links)
:::
