## Как подключить MCP-сервер

Современные сервисы уже дают свои MCP-серверы, и подключить их к Claude Code можно одной командой. Возьмём для примера Sentry, куда многие команды стримят ошибки своих приложений.

```terminal
$ claude mcp add --transport http --scope project sentry https://mcp.sentry.dev/mcp
Added HTTP MCP server sentry with URL: https://mcp.sentry.dev/mcp to project config
File modified: /path/to/repo/.mcp.json
```

::: note agent
Я проверил: после этой команды в репозитории появился файл .mcp.json, а при следующем запуске Claude Code спросит, подключать ли сервер
:::

От флага `--scope` зависит, кто увидит подключённый сервер. Уровни `local` и `user` Claude Code хранит в одном и том же файле `~/.claude.json` в твоей домашней папке, а разница между ними в том, в какое место этого файла попадёт сервер. С `user` он записывается в общий список `mcpServers` на верхнем уровне файла, и его видно во всех твоих проектах. А с `local` — в раздел `projects`, под путь текущего проекта, так что в других проектах этого сервера не будет.

| Уровень | Где хранится | Кто видит |
|---|---|---|
| `local`, по умолчанию | `~/.claude.json`, в `projects`, под путём проекта | только ты и только в этом проекте |
| `user` | `~/.claude.json`, в общем `mcpServers` | только ты, зато во всех твоих проектах |
| `project` | `.mcp.json` в корне репозитория | вся команда — файл коммитится в репозиторий |

Для команды удобнее всего уровень `project`: один раз закоммитил `.mcp.json`, и сервер появился у всех, кто работает с репозиторием.

```json title=".mcp.json"
{
  "mcpServers": {
    "sentry": {
      "type": "http",
      "url": "https://mcp.sentry.dev/mcp"
    }
  }
}
```

URL сервера в `.mcp.json` будет у всех один и тот же, а вот входить в сервис каждый будет сам, под своей собственной учёткой. Многие удалённые серверы, тот же Sentry, работают через **OAuth**, как обычный вход через браузер: ты набираешь в Claude Code команду `/mcp`, выбираешь сервер и логинишься.

И дальше агент действует в сервисе полностью от твоего имени, как будто это ты сам нажимаешь кнопки, так что если сервис ведёт журнал действий, рядом с каждым действием агента там будут стоять твоё имя и твоя аватарка.

::: note cat
Вместо самого ключа в .mcp.json пишут ссылку на переменную окружения, вроде "Authorization": "Bearer ${API_KEY}", и Claude Code подставит её значение сам — [code.claude.com](https://code.claude.com/docs/en/mcp)
:::

А если сервис даёт только API-ключ, его кладут в переменную окружения, а не в файл `.mcp.json`, потому что этот файл лежит в репозитории и всё, что в нём написано, увидят все.

::: note cat
Как подключать MCP в Codex и Antigravity CLI — [learn.chatgpt.com](https://learn.chatgpt.com/codex/mcp), [antigravity.google](https://antigravity.google/docs/mcp)
:::

Неприятно только, что у Codex и Antigravity CLI настройки MCP лежат в своих файлах:

- Codex хранит серверы для всех твоих проектов в `~/.codex/config.toml` в домашней папке, туда их и записывает команда `codex mcp add`, а сервер для одного проекта вписывают руками в `.codex/config.toml` в репозитории, и Codex прочитает этот файл, только если ты отметил проект как доверенный;
- у Antigravity CLI для всех проектов это `~/.gemini/config/mcp_config.json`, а для одного проекта — `.agents/mcp_config.json` в репозитории.

Так что если в команде пользуются разными агентами, то тот, кто сидит в Codex, не увидит MCP Sentry, подключённый для Claude Code, и подключать MCP Sentry придётся для каждого агента отдельно.
