## Когда MCP-сервера нет: API и консольные утилиты

Не у каждого сервиса есть MCP-сервер, ведь кто-то ещё не успел его сделать, а кто-то пока не видит в нём смысла. Да и практически у всех сервисов есть готовые консольные утилиты или, на худой конец, публичный API — у GitLab, например, есть утилита `glab`, у GitHub — `gh`, у AWS и Google Cloud — `aws` и `gcloud`. И агент работает с ними так же прекрасно, как и с MCP, ведь запускать команды в терминале он и так умеет.

::: note cat
Anthropic прямо пишет, что консольные утилиты — самый экономный по контексту способ работать с внешними сервисами — [code.claude.com](https://code.claude.com/docs/en/best-practices)
:::

Нужно только объяснить агенту, как ими пользоваться, и лучше всего — **скиллом**, то есть отдельной инструкцией, которую агент подгружает сам, когда она ему нужна. В скилле ты рассказываешь, какими командами создаёшь пул-реквесты, как обращаешься за данными в реплику своей продуктовой базы или заводишь новый фича-флаг в своей системе A/B-тестирования. А когда попросишь агента сделать что-то из этого, он по контексту поймёт, какой скилл подгрузить, прочитает его и вызовет нужные команды.

::: note cat
После входа glab хранит токен в системном хранилище паролей — в Связке ключей на Mac, а где такого хранилища нет — открытым текстом в своём файле настроек. В репозиторий токен не попадает ни в том, ни в другом случае — [docs.gitlab.com](https://docs.gitlab.com/cli/auth/login/)
:::

::: note cat
У самого GitLab тоже есть свой MCP-сервер: с версии 19.5 он работает на всех тарифах и на GitLab, развёрнутом на своём сервере, но включить его должен администратор — [docs.gitlab.com](https://docs.gitlab.com/user/model_context_protocol/mcp_server/)
:::

Например, если у тебя свой GitLab, развёрнутый на собственном сервере, и ты хочешь, чтобы агент создавал мерж-реквесты от твоего имени, вместо MCP можно взять утилиту `glab`. В скилле ты описываешь, какой командой создаётся мерж-реквест и какой адрес у твоего GitLab, и добавляешь, что делать, если что-то пошло не так. Если утилита не установлена, агент может поставить её сам через Homebrew, который у `glab` официально поддерживается на Mac, Linux и Windows через WSL, а может просто подсказать тебе, какую команду выполнить. А если вернулась ошибка входа, в скилле стоит объяснить, как войти и куда попадёт токен, чтобы в следующий раз всё сработало само.

```terminal
$ brew install glab
$ glab auth login --hostname gitlab.example.com
$ glab mr create --fill --draft
```

После этого `glab` установлен, ты вошёл в свой GitLab, и агент может легко создавать мерж-реквесты от твоего имени. Флаг `--fill`, кстати, возьмёт заголовок из коммитов и сам запушит ветку.

Подробнее про скиллы мы поговорим в пятой главе, а пока не стоит переживать, если у твоего любимого инструмента нет MCP, ведь если у него есть API или консольная утилита, то это тоже решение.
