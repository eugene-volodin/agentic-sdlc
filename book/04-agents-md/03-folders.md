## AGENTS.md в папках

`AGENTS.md` можно положить не только в корень, но и в любую папку внутри репозитория, допустим, в отдельное приложение в монорепозитории или в модуль со своими правилами, и описать в нём, что там лежит и что агент должен знать, работая с этой папкой. Это ещё один способ не раздувать корневой `AGENTS.md`, ведь правила одной папки агент прочитает только тогда, когда пойдёт в ней работать.

```tree title="Монорепозиторий"
shop/
├── AGENTS.md          # общее: команды, карта, словарь
├── backend/
│   └── AGENTS.md      # мастер и реплика, миграции
└── mobile/
    └── AGENTS.md      # MVVM, образец — features/profile
```

::: note cat
Чтобы Codex прочитал вложенный `AGENTS.md`, Codex запускают прямо из этой папки, например `codex --cd backend` — [learn.chatgpt.com](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
:::

Только читают такие файлы разные агенты по-разному. Claude Code подгружает `AGENTS.md` из папки, когда открывает какой-нибудь файл из этой папки. Codex же собирает все `AGENTS.md` один раз при старте, от корня репозитория до той папки, в которой ты его запустил, и вложенные файлы по ходу работы не подхватывает.

::: note caterpillar
А если в папке рядом лежит ещё и `CLAUDE.md`? Какой из них агент тогда прочитает?
:::

Если в папке рядом с `AGENTS.md` лежит `CLAUDE.md`, Claude Code прочитает только `CLAUDE.md`, а `AGENTS.md` пропустит. А если кто-то у тебя в команде заведёт себе личный `CLAUDE.local.md`, то и у него Claude Code перестанет читать `AGENTS.md`. Поэтому, как мы и договорились во второй главе, держи один `AGENTS.md` и будь внимателен с командой `/init` — создаёт она как раз `CLAUDE.md`. А если `CLAUDE.md` у тебя уже есть, напиши в нём строчку `@AGENTS.md`, и Claude Code прочитает `AGENTS.md` через неё.
