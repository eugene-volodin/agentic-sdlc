## Субагент — независимый ревьюер

::: say sparrow
А зачем отдельный агент? Можно же попросить основного агента ещё раз всё перепроверить
:::

Если в той же самой сессии, в которой агент писал код, попросить его этот код и проверить, то, скорее всего, он не найдёт ничего, что стоило бы поправить. Он ведь помнит, что собирался сделать, как и почему, и проводит ревью с тем же контекстом, с которым писал код. Поэтому я рекомендую разделять роли: один агент пишет код, другой в свежей сессии его ревьюит, а третий тестирует. Ревьюеру при этом нужны только сами изменения и правила проекта, и удобнее всего сделать его субагентом.

А что вообще такое **субагент**? По сути, это отдельный агент, которого запускает основной агент. У него своё контекстное окно, свой системный промпт и свой набор инструментов, а твоей переписки с основным агентом он не видит. На вход он получает задачу от основного агента и правила проекта из `AGENTS.md`. А когда закончит, отдаёт основному агенту только итог, без содержимого файлов, которые прочитал по дороге.

::: note cat
Каждый субагент в Claude Code — отдельный файл в папке `.claude/agents/` репозитория или в `~/.claude/agents/` домашней папки. В начале файла идёт шапка (frontmatter) — блок настроек, где указаны имя субагента, описание того, когда его звать, инструменты и модель, а ниже — его системный промпт. Проще всего попросить, чтобы субагента создал сам Claude Code — [code.claude.com](https://code.claude.com/docs/en/sub-agents)
:::

Ревьюеру не нужно ничего править, поэтому дай ему возможность только читать файлы и искать по коду. Чтобы смотреть дифф, ему понадобится ещё и терминал, а через терминал можно и править файлы. Поэтому все команды, кроме `git diff`, ему стоит запретить хуком, который прописывают прямо в шапке файла этого субагента, и тогда он не начнёт сам править код вместо того, чтобы написать о проблеме. Учти, что Claude Code выполняет хуки из шапки субагента только тогда, когда ты уже подтвердил, что доверяешь папке проекта, а при запуске через `claude -p` не выполняет их вовсе. Подробнее о хуках-запретах мы поговорим в следующей главе, о безопасности.

Так же устроен и скилл `/pr-review` из главы про скиллы, который проверяет пул-реквест. В нём несколько субагентов смотрят на одни и те же изменения, каждый по своей теме, а потом основной агент собирает их находки в один список.

```prompt who=cat title="Субагент-ревьюер" note="-"
Создай в .claude/agents/ субагента reviewer, который проверяет изменения моей ветки относительно main.
Дай ему только чтение файлов и поиск по коду. Терминал дай, но хуком запрети в нём всё, кроме git diff.
Что важно проверять в нашем проекте, возьми из AGENTS.md и из скилла ревью, если он есть, а не придумывай.
Пусть он отвечает списком: файл и строка, что не так, почему это важно и насколько это серьёзно. Если замечаний нет, пусть так и пишет.
Покажи файл до записи.
```

После того как агент закончил писать код, попроси его проверить этот код субагентом, например: «Проверь мою ветку субагентом reviewer». Только помни, что свежий ревьюер, в отличие от агента, который писал код, всегда что-нибудь найдёт, даже там, где всё в порядке, потому что его просили искать проблемы. Поэтому бери из его отчёта только то, что влияет на работу кода, а проблемы со стилем и форматированием пусть ловит линтер.

::: note cat
У Claude Code есть и встроенные субагенты. Например, Explore умеет только искать и читать код, и Claude Code сам отдаёт ему поиск, чтобы не засорять контекст основного агента — [code.claude.com](https://code.claude.com/docs/en/sub-agents)
:::
