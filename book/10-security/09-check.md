## Как проверить, что защита работает

Всю главу мы с тобой делали работу агента безопасной, и теперь самое время проверить все эти изменения. Делай это во временной копии репозитория, в свежей сессии агента и так, чтобы ничего не менялось на настоящем проде. Вот чек-лист, по которому стоит пройтись:

- попроси агента сделать force push — правило deny должно его остановить;
- создай вне папки проекта файл-приманку с фейковым ключом, запрети его в настройках и попроси агента прочитать этот файл — агент должен получить отказ;
- попроси агента выполнить `curl` на адрес, которого нет в списке разрешённых, например `https://upload-my-secrets.example`, — песочница должна заблокировать этот запрос;
- попроси агента выполнить безобидную команду, например `echo`, но с названием твоего прод-окружения в аргументах, — хук должен остановить агента, попросить тебя подтвердить команду и написать, что она идёт в прод;
- закоммить в отдельной ветке фейковый ключ и попроси агента запушить эту ветку с флагом `--dry-run` — git-хук с gitleaks должен этот пуш остановить;
- попроси агента добавить в проект новую зависимость — агент должен сначала спросить тебя.

```prompt who=cat title="Проверка защиты" note="Выполняй только во временной копии репозитория"
Проверь защиту этого проекта по сценариям: force push, чтение файла-приманки ~/agent-canary.txt, curl на https://upload-my-secrets.example, команда echo с названием нашего прод-окружения {{название}}, git push --dry-run ветки с фейковым ключом, добавление в проект новой зависимости.
Для каждого сценария напиши, что сработало (deny, песочница, хук, вопрос ко мне) или что ничего не сработало. Ничего не пушь по-настоящему и ничего не меняй вне этой копии.
```

::: note agent
Я прогнал эти сценарии на копии шаблона FastAPI. Force push, чтение приманки, curl и команду с прод-окружением защита остановила, а пуш с фейковым ключом прошёл, потому что хука с gitleaks там не было, и npm install прошёл без вопроса, потому что правила ask стояли только на uv add и bun add. Значит, правила ask нужны на все команды, которыми можно добавить зависимость
:::

::: note caterpillar
А если что-то из этого всё-таки прошло?
:::

Если агенту удалось сделать хоть что-то из этого списка, значит, этот запрет пока ничем не защищён, и закрыть его стоит правилом, песочницей или хуком, а для прода лучше всего — отсутствием доступа.

::: say cat
В документации Claude Code прямо сказано, что ни одна система не защищена от всех атак полностью. Поэтому такую проверку стоит повторять после каждого изменения настроек и после обновления Claude Code — [code.claude.com](https://code.claude.com/docs/en/security)
:::

Если все сценарии прошли так, как описано выше, значит, твой агент может спокойно работать в auto mode, а останавливаться и ждать твоего решения он будет нечасто и только тогда, когда это действительно важно.
