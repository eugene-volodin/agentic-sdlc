## Вредоносный код в библиотеках

Ни один проект не обходится без сторонних библиотек, которые мы ставим в него как зависимости. Только вместе с библиотекой в проект может попасть и вредоносный код, который в неё кто-то добавил. У многих пакетных менеджеров библиотека может запустить свой код прямо во время установки, и этот код выполняется с твоими правами раньше, чем ты успеешь на него посмотреть. А ставит библиотеки теперь агент, и auto mode разрешает ему ставить всё, что уже записано в файлах зависимостей проекта.

::: note cat
31 марта 2026 года злоумышленники угнали npm-аккаунт ведущего мейнтейнера axios и выпустили версии 1.14.1 и 0.30.4 с новой зависимостью, которая ставила на компьютер троян удалённого доступа. Эти версии провисели в npm около трёх часов, пока их не удалили — [github.com/axios](https://github.com/axios/axios/issues/10636)
:::

::: note cat
В сентябре 2025 года через фишинг взломали аккаунт мейнтейнера 18 пакетов, которые вместе скачивают больше двух миллиардов раз в неделю, среди них chalk и debug. В их новые версии добавили код, который в браузере подменял адреса криптокошельков в переводах — [aikido.dev](https://www.aikido.dev/blog/npm-debug-and-chalk-packages-compromised)
:::

Бывает, что вредоносный код живёт в библиотеке месяцами, как было с event-stream. Но чаще заражённую версию замечают и удаляют за несколько часов, как было с axios. Поэтому лучше всего здесь работает **карантин свежих версий** (cooldown) — правило, по которому пакетный менеджер не ставит версию, если она вышла меньше нескольких дней назад. За это время её успеют проверить другие, и если с ней что-то не так, она просто не дойдёт до тебя.

Вот как это сейчас настраивается в самых популярных пакетных менеджерах:

| Менеджер | Как включить карантин свежих версий | Что с кодом, который выполняется при установке |
|---|---|---|
| npm 12 | Настройка `min-release-age` в днях, по умолчанию карантин выключен | Скрипты установки у зависимостей по умолчанию заблокированы |
| pnpm 11+ | Настройка `minimumReleaseAge`, по умолчанию карантин — сутки | Скрипты установки у зависимостей заблокированы, разрешить их можно через `allowBuilds` |
| Yarn 4.15+ | Настройка `npmMinimalAgeGate`, по умолчанию карантин — сутки | Скрипты установки по умолчанию выключены настройкой `enableScripts` |
| pip 26.1+ | Флаг `--uploaded-prior-to`, например `P3D` — три дня | Пакеты из исходников при установке выполняют код сборки, и флаг `--only-binary :all:` это запрещает |
| uv | Настройка `exclude-newer`, например `"1 week"` | Настройка `no-build` запрещает собирать пакеты из исходников |
| Poetry 2.4+ | Настройка `solver.min-release-age` в днях, по умолчанию карантин выключен | — |
| Composer 2.11 | Настройка `policy.cooldown.period`, по умолчанию карантин выключен | Плагины не запускаются, пока их не разрешили в `allow-plugins` |

::: say cat
У Maven и Gradle своего карантина я не нашёл, зато в них можно включить проверку контрольных сумм пакетов, чтобы никто не смог подменить уже записанную версию. Настройки — на 31 октября 2026 года: [docs.npmjs.com](https://docs.npmjs.com), [pnpm.io](https://pnpm.io/settings), [yarnpkg.com](https://yarnpkg.com/configuration/yarnrc), [pip.pypa.io](https://pip.pypa.io/en/stable/cli/pip_install/), [docs.astral.sh/uv](https://docs.astral.sh/uv/concepts/resolution/), [python-poetry.org](https://python-poetry.org/docs/configuration/), [getcomposer.org](https://getcomposer.org/doc/06-config.md)
:::

Если же зависимости у тебя обновляет бот, то карантин стоит включить и у него. Dependabot по умолчанию и так ждёт три дня после выхода новой версии, кроме обновлений безопасности, а в Renovate для этого есть настройка `minimumReleaseAge`.

Ну и конечно же, агент должен ставить зависимости строго из файлов зависимостей проекта, а добавлять новую зависимость — только после того, как спросит тебя, ведь новая зависимость — это новый сторонний код в проекте. А ещё агент может выдумать название библиотеки, которой не существует, и если злоумышленник уже успел зарегистрировать библиотеку с таким названием, то агент поставит именно её. Осторожным стоит быть и с плагинами для Claude Code: плагин выполняет свой код с твоими правами, и ни правила, ни песочница его не проверяют.

```prompt who=cat title="Карантин зависимостей" note="-"
Определи, какие пакетные менеджеры есть в проекте, и для каждого включи карантин свежих версий, например на неделю, и запрет скриптов установки у зависимостей, если менеджер это умеет.
Если зависимости обновляет Dependabot или Renovate, настрой ожидание и у него, но обновления безопасности не задерживай.
Добавь в .claude/settings.json правила ask на команды, которые добавляют новую зависимость, но не на установку уже записанных зависимостей.
Проверь, что установка и тесты проходят, покажи, что поменял, и дай ссылку на документацию к каждой настройке.
```
