## Когда агенту нужно спрашивать разрешение

Раньше я согласовывал с агентом каждую правку: какой файл записать, какую команду вызвать. Я всё это ревьюил, и это требовало очень много сил, энергии и времени и, по сути, сводило всю работу с агентом на нет. Сейчас я работаю в основном в **auto mode** — режиме, в котором агент почти всё делает сам, а там, где нужно моё решение, его останавливают ограничения и хуки.

И вот тут я пришёл к простому правилу — **ситуаций, когда агент останавливается и ждёт от тебя подтверждения, должно быть мало, и каждая должна быть по делу.** Если агент спрашивает тебя по каждой мелочи, то очень скоро ты устаёшь читать его вопросы и начинаешь подтверждать всё подряд, а вместе с десятками безобидных команд однажды подтвердишь и опасную.

::: note cat
Anthropic посчитала, что пользователи Claude Code подтверждают около 93% таких вопросов агента. То есть человек долго не может внимательно читать каждый из них, и вопрос, который появляется слишком часто, уже ни от чего не защищает — [anthropic.com](https://www.anthropic.com/research/how-we-contain-claude)
:::

У Claude Code есть несколько режимов работы, и они как раз отличаются тем, что агент делает сам и где он останавливается и спрашивает тебя:

| Режим | Что агент делает без твоего подтверждения | Когда подходит |
|---|---|---|
| Manual | Агент только читает файлы, а на всё остальное спрашивает тебя | Когда ты хочешь проверять каждое действие агента |
| plan | Агент только читает файлы и составляет план, но ничего не меняет | Когда нужно сначала разобраться в задаче |
| acceptEdits | Агент читает и правит файлы и вызывает файловые команды вроде `mkdir`, `mv` и даже `rm`, но только внутри папки проекта | Когда ты сидишь рядом и смотришь на правки |
| auto | Агент делает почти всё сам, но перед рискованными действиями их проверяет отдельная модель | Для обычной ежедневной работы |
| dontAsk | Агент делает только то, что ты разрешил заранее, а всё остальное ему сразу запрещено | Для CI и скриптов, где спрашивать некого |
| bypass | Агент делает всё без всяких проверок | Только в изолированном контейнере или виртуальной машине |

В auto mode работает отдельная модель, которая проверяет действия агента, и её называют **классификатором**. Читать и править файлы внутри проекта агент может и без неё, а вот перед остальными действиями классификатор смотрит на твои сообщения и на команду, которую агент собирается выполнить, и решает, не выходит ли она за рамки твоей просьбы и не опасна ли. Этим auto mode и отличается от режима bypass, в котором ничего подобного нет и агент выполняет любую команду без проверки.

::: note cat
В интерактивных сессиях Claude Code auto mode стал режимом по умолчанию на всех тарифах с сентября 2026 года. А про режим bypass в документации прямо сказано, что он не защищает ни от промпт-инъекций, ни от случайных действий — [code.claude.com](https://code.claude.com/docs/en/permission-modes)
:::

По документации Claude Code, классификатор по умолчанию блокирует:

- force push, `git reset --hard` и `terraform destroy`;
- деплой и миграции на прод;
- запись в хранилище секретов;
- запуск скриптов, скачанных из интернета.

Но кое-что он по умолчанию разрешает, и об этом важно помнить:

- читать `.env` и использовать ключи оттуда по назначению, например отправлять ключ от платёжного сервиса в API этого сервиса;
- пушить в любую ветку репозитория, даже в `main`;
- ставить зависимости, которые уже записаны в файлах зависимостей проекта, например в `package-lock.json`, `pom.xml` или `requirements.txt`.

::: note cat
В июле 2025 года агент Replit удалил продакшн-базу, хотя пользователь объявил в чате запрет на любые изменения. Генеральный директор Replit назвал это недопустимым, и после этого Replit разделил базы для разработки и для продакшена, чтобы таких случаев больше не было — [x.com/amasad](https://x.com/amasad/status/1946986468586721478)
:::

Записывай правилами в настройках Claude Code всё, что хочешь запретить, и всё, на что агент должен спрашивать твоего разрешения. Общие для команды правила лежат в `.claude/settings.json` в репозитории, а личные — в `~/.claude/settings.json`. Правила бывают трёх видов:

- **deny** — запретить совсем;
- **ask** — всегда спрашивать тебя, даже в auto mode;
- **allow** — разрешить без вопросов.

```json title=".claude/settings.json"
{
  "permissions": {
    "deny": ["Bash(git push *--force*)", "Bash(git push -f *)", "Bash(git push * -f *)"],
    "ask": ["Bash(git push * main)"],
    "allow": ["Bash(npm test *)"]
  }
}
```

Сама программа Claude Code проверяет эти правила, и как бы модель ни рассуждала, обойти их она не сможет. Сначала проверяется deny, потом ask и только потом allow, и запрет действует в любом режиме, даже в bypass. А правило ask останавливает агента и в auto mode, причём ответить на такой вопрос можно только «да» или «нет», кнопки «больше не спрашивать» у него нет.

Запрещать при этом стоит только то, что действительно опасно, иначе агент снова будет останавливаться слишком часто. Например, я сам прошу агента поставить аппрув на пул-реквест через `gh`, поэтому такие команды у меня не запрещены.

::: note caterpillar
А если агент вызовет git по полному пути или спрячет команду в скрипт?
:::

Правило смотрит только на текст команды, а не на то, что эта команда сделает на самом деле. Если агент запустит ту же программу по полному пути, через `sh -c` или спрячет её внутрь скрипта, то правило её уже не узнает. Даже force push можно записать так, что правила его не узнают, например `git push origin +main`. Правила в настройках закрывают обычные команды, которыми агент чаще всего и пользуется, а от таких обходов защитит только песочница или вообще отсутствие у агента доступа. А force push в `main` стоит запретить ещё и в настройках самого репозитория: в GitHub для этого в ruleset ветки `main` есть правило «Block force pushes», и в новом ruleset оно включено сразу.

```prompt who=cat title="Три списка" note="-"
Прочитай .claude/settings.json, ~/.claude/settings.json и AGENTS.md и скажи, какой режим задан в defaultMode и какие правила уже есть.
Предложи для этого проекта три списка: deny — что запретить совсем, ask — на что всегда спрашивать меня, allow — что делать без вопросов (тесты, линтер, сборка).
Для каждого правила напиши, от чего оно защищает.
Покажи итоговый JSON и запиши его в .claude/settings.json только после моего «да».
```
